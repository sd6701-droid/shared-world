# CLAUDE.md — The Two Thieves (pass 1 build spec)

> This file is the build plan and the single source of truth for the agent and
> teammates. Read it top to bottom before writing code. Pass 1 is scoped to
> roughly **2 hours of Claude Code build time**. Everything in "Pass 2" is added
> later **without changing the server's shape**, so do not build any of it now.

---

## 0. One-paragraph overview

**The Two Thieves** is a two-player, competitive museum heist. Two real people,
**Goggles** and **Cameras**, each at their own laptop, race to find a brass
compass hidden on one floor of a museum at night, then get it out through an
exit before time runs out. A scripted guard patrols the floor. A third screen
shows the whole floor plan to the audience. When a player walks into a room,
their screen switches to a live first-person view of that room generated by
**Lingbot-World-2** (via Reactor), styled through their role's "lens": green
night-vision for Goggles, grainy black-and-white CCTV for Cameras.

### The core invariant (NEVER violate this)

**The map is the only truth. The Reactor models only decide what people see.**

- Every rule (movement, catches, search, steal-back, win/lose) is decided by the
  game server against the map grid. Nothing is ever decided from what a model
  rendered.
- A model session can fail, lag or hallucinate and the game must keep running
  correctly. The map never depends on a session.
- If a change would let a rendered view affect game outcome, that change is
  wrong. Route it through the server's `GameState`.

## 1. Design decisions (and why)

| Question | Decision | Why |
|---|---|---|
| Map markers | Colored dots with labels: **green** = Goggles, **grey** = Cameras, **yellow** = guard with a vision cone | The audience reads a map at a glance; avatars on a map add nothing |
| Room view | Egocentric (first person) | Lingbot-World-2 is first-person from a seed image, so the player is never drawn and identity consistency never comes up |
| Thieves | Real people at keyboards, never rendered | Nothing to keep consistent |
| Other thief in your room | Not shown in the room view in pass 1; the showdown is decided on the map | Avoids rendering a second person in a generated world |
| Guard | A scripted NPC on the map with a deterministic patrol; catches are map-based | Fair and testable. The webcam avatar (Vidu-S2-Avatar) is a pass-2 visual on Cameras' screen, never the rule |
| Seed images | Pre-generated with Nano Banana (Gemini image API) the night before, one per room, one shared style prompt | Consistent museum look across rooms; the compass room gets a variant with the compass on a pedestal |

## 2. Pass 1 scope

Pass 1 is **a playable two-player round on one floor** with Lingbot-World-2 room
views, a scripted guard, and text banners for story beats.

### In

- One floor, **6 rooms** joined by a corridor loop, drawn from a JSON map
- Two roles (Goggles, Cameras), a map screen, a settings page
- One Lingbot-World-2 room session per player: opened on room entry, closed on
  exit; the lens is set by prompt
- Compass hidden in one room; press `E` to search; found only if the server says
  you are in that room
- Guard dot on a fixed patrol; a thief in the guard's vision cone is sent back to
  start with a 30 s penalty
- Three beats as text banners on a server timer: **leak** (0:00), **lockdown**
  (3:00), **alarm** (on pickup, 90 s)
- **Win:** the compass holder reaches an exit before the timer runs out.
  **Lose:** the timer hits zero.

### Out (pass 2, do not build)

Pre-warming the next room, Fast-H3 beat clips, Vidu-S2-Editing lens pass and
disguise, Vidu-S2-Avatar guard, multi-floor, hidden stairwell, showdown
rendering, guard audio. See §12.

## 3. Architecture

```
                 ┌────────────────────────────────────────┐
                 │  server/  (Node + Socket.IO, :3001)     │
                 │  GameState: the ONLY place rules run    │
                 │  map, players, guard, compass, timers,  │
                 │  beats, win/lose — ticks at 10 Hz       │
                 └───────┬───────────────┬───────────┬─────┘
          state / banner │               │           │ state (full)
          roomEnter/Exit │               │           │
                ┌────────▼─────┐ ┌───────▼──────┐ ┌──▼──────────┐
                │ /play?role=  │ │ /play?role=  │ │ /map        │
                │   goggles    │ │   cameras    │ │ (audience)  │
                └──────┬───────┘ └──────┬───────┘ └─────────────┘
       on roomEnter:   │                │
       JWT from /api/token, then Reactor session (lingbot-world-2)
                       ▼                ▼
                 room video (lens = prompt)   ← visual only, never a rule
```

One **Next.js app** plus one small **Socket.IO game server** in the same repo.
The game server is the truth; the Next.js app renders screens and talks to
Reactor.

| Part | Runs where | Responsibility |
|---|---|---|
| `server/` (Node + Socket.IO, port 3001) | One process | Map, player positions, guard patrol, compass, timers, beats, win/lose. Broadcasts state at 10 Hz |
| `app/` (Next.js, port 3000) | Browser + API routes | Role select, map screen, play screen, settings page; mints Reactor JWTs server-side |
| `app/api/token` | Next.js API route | Exchanges the Reactor API key for a session JWT via `POST https://api.reactor.inc/tokens`; never exposes the key |
| `app/api/settings` | Next.js API route | Reads and writes keys for the current process (see §5) |
| `public/rooms/` | Static files | Seed images, one per room, plus the compass variant |
| `scripts/gen-rooms.ts` | Run once, the night before | Generates seed images with the Gemini image API (Nano Banana) from `map.json` prompts |
| `map.json` | Shared by server, app and script | Rooms, doors, exits, guard route, compass room, start positions |

## 5. Settings page and key handling

`/settings` is a plain form for two keys. **Keys live only on the server side of
the Next.js app and are never sent to the browser.**

- **Fields:** Reactor API key (`rk_...`) and Gemini API key (used by the
  room-image script). Each field shows a status chip: *set* / *not set*, plus the
  last 4 characters when set. Never return the full key in any response.
- **Submit** posts to `/api/settings`, which stores the values in server memory
  and appends them to `.env.local` as `REACTOR_API_KEY` and `GEMINI_API_KEY` so
  they survive a restart. `.env.local` **must** be in `.gitignore`. Check this
  before the first commit.
- **On boot**, the server reads `.env.local` first, so keys set once stay set.
- **"Test Reactor key"** calls `/api/token`. Success means a JWT came back.
- **"Test Gemini key"** generates one 256 px test image.
- The **map screen shows a red banner** if either key is missing, linking to
  `/settings`.

### Reactor JWT route

`/api/token` mints a short-lived, session-scoped token per player on request.
The browser receives **the JWT and the model slug, nothing else**.

### Implementation notes

- Keep the in-memory key store on a module-level singleton (e.g. on
  `globalThis`) so Next.js dev hot-reload doesn't drop it between requests.
- When appending to `.env.local`, replace an existing line for the same key
  rather than adding duplicates.
- `/settings` has no auth. That is acceptable for a hackathon on a trusted
  network only. Don't expose port 3000 publicly.

## 6. Map data, rooms and seed images

`map.json` defines a **20 × 12 cell grid**: 6 rooms around a corridor loop, two
exits at opposite corners, two start cells next to the exits, one compass room,
and the guard route as an ordered list of cells.

### Suggested shape

```jsonc
{
  "width": 20, "height": 12,
  // one string per row; one char per cell, e.g. '#' wall, '.' corridor,
  // a room letter for room cells, 'X' exit
  "grid": ["####################", "..."],
  "rooms": {
    "lobby":       { "label": "Lobby",        "char": "L", "prompt": "..." },
    "maritime":    { "label": "Maritime Hall","char": "M", "prompt": "..." },
    "antiquities": { "label": "Antiquities",  "char": "A", "prompt": "..." },
    "archive":     { "label": "Archive",      "char": "R", "prompt": "..." },
    "gallery":     { "label": "Gallery",      "char": "G", "prompt": "..." },
    "dock":        { "label": "Loading Dock", "char": "D", "prompt": "..." }
  },
  "doors": [[x, y], ...],
  "exits": { "A": [x, y], "B": [x, y] },          // A in Lobby, B in Loading Dock
  "starts": { "goggles": [x, y], "cameras": [x, y] },
  "compassRoom": "archive",
  "guardRoute": [[x, y], ...],                     // ordered, loops back to [0]
  "styleSuffix": "photorealistic, museum interior, night, 16:9, no people, no text, consistent warm tungsten lighting",
  "compassSuffix": "a small brass compass on a lit pedestal in the center"
}
```

Cells are `[x, y]`, with `x` in 0..19 and `y` in 0..11, origin at the top-left.
Use one convention everywhere: server, map screen, minimap.

### Rooms

| Room | Seed-image prompt (the shared style is appended) | Notes |
|---|---|---|
| Lobby | Grand marble museum lobby at night, ticket desk, closed gift shop | Exit A opens here |
| Maritime Hall | Hall of ship models in glass cases, old maps on walls | Faces the river (the Cameras hint) |
| Antiquities | Stone statues and amphorae on plinths, dim spotlights | |
| Archive | Narrow room of wooden drawers and ledgers, one desk lamp | **Compass room in pass 1** (set in `map.json`) |
| Gallery | Long gallery of oil paintings, velvet rope, parquet floor | |
| Loading Dock | Concrete loading dock, crates, roll-up door | Exit B opens here |

**Shared style prompt:** `photorealistic, museum interior, night, 16:9, no people,
no text, consistent warm tungsten lighting`

The compass room also gets a second image with `a small brass compass on a lit
pedestal in the center`.

### `scripts/gen-rooms.ts`

- Reads prompts from `map.json`, calls the Gemini image generation API with
  `GEMINI_API_KEY`.
- **Reads the model name from `GEMINI_IMAGE_MODEL`**. Do not hard-code it; the
  Nano Banana model id changes.
- Writes `public/rooms/<room>.png` (6 files) and
  `public/rooms/<compassRoom>-compass.png` (1 file): **7 images total**.
- Skips images that already exist unless `--force` is passed, so a re-run
  doesn't burn quota.
- Run it **the night before**. The game must work with the images on disk and no
  Gemini access on the day.

## 7. Game server: rules, state and events

The server owns **one `GameState` object**, ticks at **10 Hz**, and is the
**only** place a rule is decided.

```ts
type Role = 'goggles' | 'cameras';

interface GameState {
  phase: 'lobby' | 'playing' | 'alarm' | 'over';
  clock: number;              // seconds since start
  players: Record<Role, {
    cell: [number, number];
    room: string | null;
    hasCompass: boolean;
    penaltyUntil: number;
  }>;
  guard: { cell: [number, number]; routeIndex: number; facing: 'N' | 'E' | 'S' | 'W' };
  compassRoom: string;
  lockedRooms: string[];
  winner: Role | null;
}
```

Add any internal bookkeeping the rules need (e.g. per-player seconds spent in
the compass room, room-entry timestamps for steal-back, alarm deadline). Keep
it server-side and out of the client payload unless a screen needs it.

### Events

**Client → server**

| Event | Notes |
|---|---|
| `join(role)` | Claims a role. A second `join` for a taken role is rejected. `/map` joins as a spectator |
| `move(dir)` | One cell per call; **rate-limited to 4/s** per player; ignored during penalty |
| `search()` | See rule 3 |
| `grab()` | Bound to `G` (grab/drop the compass). See §11 Q6 for pass-1 behavior |

**Server → client**

| Event | Notes |
|---|---|
| `state` | Every tick. Filtered per recipient (see rule 7) |
| `banner(role \| 'all', text, seconds)` | Story beats, catches, alarms |
| `roomEnter(role, room)` / `roomExit(role, room)` | Drive the Lingbot session lifecycle |
| `gameOver(winner)` | `winner` is a `Role` or `null` (arrested) |

### Rules

1. **Movement.** A cell is walkable if it is a corridor or room cell and the room
   is not locked for that role. Entering or leaving a room emits `roomEnter` /
   `roomExit`.
2. **Guard.** Advances one cell along the route **every second**. Its vision cone
   is **the 3 cells ahead** in `facing`. A thief inside a room cell in the cone
   is caught: teleported to start, `penaltyUntil = clock + 30`, and a banner goes
   to that player.
3. **Search.** `search()` succeeds only if `players[role].room === compassRoom`
   **and** the player has stood in that room for **5 s total**. On success the
   compass is shown on the map and that player gets `hasCompass`.
4. **Beats.**
   - **0 s (leak):** banner to Goggles: *"Tip: the compass is on this floor's
     east side"*; banner to Cameras: *"Tip: a room facing the river"*. There is
     one floor in pass 1, so the hints point at halves of the floor.
   - **180 s (lockdown):** lock the two rooms nearest the compass room for
     whoever is not inside them.
   - **On `hasCompass` (alarm):** `phase = 'alarm'` with a **90 s countdown**.
5. **Steal-back.** If both players are in the same room during alarm, the
   compass passes to the player who **entered the room most recently**. The map
   shows the handoff.
6. **End.** The holder reaches an exit cell, so `winner = holder`. The countdown
   reaches 0, so `winner = null` and `phase = 'over'`.
7. **Cameras extras.** Cameras' state payload includes the **guard's cell and
   facing** and **Goggles' last corridor cell**. Goggles' payload omits both.
   `/map` gets the full state.

### Engineering rules for the server

- Write the rules as **pure functions** (`tick(state, dt)`,
  `move(state, role, dir)`, ...) and keep sockets and `setInterval` in a thin
  shell around them. Tests drive `tick()` directly with a fake clock.
- **Deterministic:** no `Math.random()` in rules. The guard route and the
  compass room come from `map.json`.
- **Disconnect-safe:** a socket dropping (browser killed mid-room) must not crash
  the server or stall the tick. The other player can finish the round.
- Socket.IO must allow CORS from the Next.js origin(s). The players are on
  different laptops, so the client reads the server URL from
  `NEXT_PUBLIC_GAME_SERVER_URL` (default `http://localhost:3001`) and on the day
  it is set to the host laptop's LAN IP.

## 8. Client pages

Four routes, all reading the **same state stream** from the game server.

| Route | Who opens it | Shows |
|---|---|---|
| `/` | Everyone | Role picker: Goggles, Cameras, Map. Key-status banner linking to `/settings` |
| `/map` | The audience laptop | Full floor plan, both dots, guard dot with cone, locked rooms hatched, compass icon once found, countdown, winner overlay |
| `/play?role=goggles` | Player 1 | Room view (Lingbot stream) full-screen when in a room; corridor view when not; a 200 px minimap bottom-left showing **only its own dot**; banners; clock |
| `/play?role=cameras` | Player 2 | Same layout, CCTV lens; the minimap **also** shows the guard dot and cone and Goggles' last corridor cell |
| `/settings` | Organizer | Keys, status, test buttons |

- **Corridor view (pass 1):** a static 2D top-down view of the corridor segment
  with the player's dot, drawn on canvas. **No model call outside rooms**, which
  keeps costs and latency down.
- **Controls:**
  - `WASD` moves one cell per press on the map, and is also forwarded to the
    room session while in a room.
  - `E` searches.
  - `G` grabs or drops the compass.
  - Keys are handled **once, in a single hook** (`useControls`) so the map move
    and the room-session move never disagree.
- **Banners:** 3 s overlays at the top, colored by sender: **gold** for tips,
  **red** for alarm, **grey** for guard events.
- The client never computes rules. It renders the last `state` it received.

## 9. Room view: Lingbot-World-2 session lifecycle

Each player holds **at most one** Lingbot-World-2 session, opened on `roomEnter`
and closed on `roomExit`. **The lens is a prompt, nothing more.**

1. **On `roomEnter(role, room)`:** fetch a JWT from `/api/token`, create
   `new Reactor({ modelName: 'reactor/lingbot-world-2' })`, then `connect(jwt)`.
2. **On status `ready`:**
   - `uploadFile(public/rooms/<room>.png)`, or the `-compass` variant when
     `room === compassRoom`
   - `sendCommand('set_image', { image })`
   - `sendCommand('set_prompt', { prompt: lensPrompt[role] })`
   - `sendCommand('start', {})`
3. Attach the `main_video` track to the full-screen `<video>`. Show a **"door
   opening"** overlay until the first frame arrives.
4. **While in the room:** forward WASD and mouse-look to the session using **the
   exact command names from the schema page** (do not guess them).
5. **On `roomExit`:** `disconnect()` (this is non-recoverable; a new room means a
   new session), tear down the video, return to the corridor view.
6. **On any session error:** show the seed image as a still with a **"signal
   lost"** overlay and keep the game running. The map never depends on the
   session.

### Guardrails

- **Cost:** sessions bill **per second while open**, so the exit teardown must be
  reliable. Close the session on `roomExit`, on page unload (`pagehide`), on
  socket disconnect, and on component unmount.
- **Idle timeout:** close a session if **no input arrives for 60 s**.
- **Race:** if the player leaves a room before the session is `ready`, cancel and
  disconnect it. Never let two sessions exist for one player.
- **Pass-1 compass:** the `-compass` seed image is used whenever the room is
  the compass room. Whether to switch back to the plain image after the compass
  is taken is a pass-2 nicety.

### Lens prompts (`lib/lenses.ts`)

- **Goggles:** `night-vision goggles view, monochrome green, bright center, dark
  vignette edges, slight grain, first person`
- **Cameras:** `security camera footage, black and white, grainy, high corner
  angle, slight fisheye, timestamp overlay style, first person`

## 10. Build order (suggested, about 2 h)

Each step ends in a working state. Commit after each one.

1. **Skeleton + keys (15 min).** Scaffold, `.gitignore` with `.env.local`,
   `/settings`, `/api/settings`, `/api/token`, both test buttons. *Exit: the
   Reactor test returns a JWT.*
2. **Seed images (10 min, ideally the night before).** `map.json` room prompts and
   `scripts/gen-rooms.ts`. *Exit: 7 PNGs in `public/rooms/`.*
3. **Map + server core (25 min).** `map.json` grid, `server/` with `GameState`,
   `join`, `move`, rooms, `roomEnter`/`roomExit`, 10 Hz broadcast. `/map` draws the
   grid and dots. *Exit: two browsers move dots on the map screen.*
4. **Rules (25 min).** Guard patrol + cone + catches + penalty, search with 5 s
   dwell, beats (leak, lockdown, alarm), steal-back, win/lose, per-role state
   filtering. Unit tests for each rule. *Exit: a full round plays out on the map
   screen with no model calls.*
5. **Play screen (20 min).** `/play`, corridor canvas, minimap (role-filtered),
   banners, clock, the single controls hook. *Exit: the round plays on two
   laptops plus the map screen.*
6. **Room sessions (25 min).** `roomSession.ts` lifecycle, lens prompts, error
   fallback, idle timeout, teardown on every exit path. *Exit: walking into a room
   streams within 10 s; leaving brings the Reactor session count back to 0.*

Steps 1–5 are a complete, demoable game without Reactor. Step 6 is the visual
layer, and the game must still work if it fails.

## 11. Open questions (the spec is ambiguous; resolve before or while building)

The decision on each line is a default. Change it if the team decides otherwise,
and update this file.

1. **Hints vs compass room.** The Cameras hint points at Maritime Hall ("faces
   the river"), but the compass is in the Archive. *Default:* lay out the map so
   Maritime Hall and Archive are neighbours on the east side, so both hints
   narrow the search without being wrong. Confirm whether the river hint is meant
   to mislead.
2. **Corridor catches.** Rule 2 catches only "a thief inside a room cell in the
   cone", but the acceptance test says "walking into the guard's cone". *Default:*
   catch on **any walkable cell** in the cone, and walls block the cone (stop at
   the first wall cell).
3. **Round timer.** Only the 90 s alarm countdown is specified, and a round must
   take under 8 min. *Default:* a **6:00 round clock**; on pickup the
   remaining time becomes `min(remaining, 90 s)`. Lockdown fires at 3:00 of the
   round clock.
4. **"Nearest" rooms for lockdown.** *Default:* shortest walkable path from the
   compass room's door to each other room's door; ties go to `map.json` order.
   Store the result in `map.json` as `lockdownRooms` so it's explicit and
   testable.
5. **Penalty.** *Default:* during `clock < penaltyUntil` the player is frozen at
   start and `move` is ignored.
6. **`grab()` / `G` in pass 1.** Search already grants `hasCompass`. *Default:*
   `G` drops the compass on the player's cell (the map shows it) and `G` on that
   cell picks it up again, so the compass is never lost. If that's not wanted,
   make `grab()` a no-op in pass 1 and keep the event for the pass-2 disguise.
7. **Holder caught during alarm.** *Default:* the compass drops on the cell where
   the holder was caught, the alarm keeps running, and either player can grab it.
8. **Exits.** *Default:* either exit wins for the holder, regardless of role.
9. **Lobby → playing.** *Default:* the round starts when both roles have joined,
   or when the map screen presses Start.

## 13. Pass-2 backlog (do NOT build in pass 1)

In priority order. Each is additive and touches the server **only through new
events**.

1. **Pre-warm the next room.** When a player is within 2 cells of a door, open
   that room's session early; swap on entry; close the previous one. Removes the
   10 s wait.
2. **Vidu-S2-Avatar guard.** A teammate on webcam becomes the uniformed guard;
   the stream appears in a CCTV panel on Cameras' screen whenever the guard's cell
   is a camera cell; mic audio passes through. The server adds
   `guardOnCamera(bool)`.
3. **Fast-H3 beat clips.** Replace banners with 5 to 10 s clips generated from
   state (which thief, which room, outcome) for leak, lockdown, alarm, caught,
   win, arrested. Prompt templates live in `beats.json`.
4. **Vidu-S2-Editing lens pass.** Each beat clip is edited into the two lenses
   so both players see the same beat their own way.
5. **Disguise.** One guard cap per floor; `grab()` on it triggers a
   Vidu-S2-Editing try-on of the player's avatar on the map screen and 30 s of
   guard immunity.
6. **Showdown rendering.** When both players are in one room, use one Lingbot
   session plus a Vidu-S2-Editing lens pass for the second player.
7. **Second floor and hidden stairwell,** with the lockdown moving to "floor two
   seals".

## 14. Guardrails (read before each decision)

- **The map is the only truth.** If a feature needs a model's output to decide
  something, redesign it so the server decides and the model only shows it.
- **Never guess Reactor command names.** Read the schema page.
- **Never send API keys to the browser.** The browser gets a JWT and a model slug.
- **Every open session costs money per second.** Every exit path closes it.
- **Steps 1–5 of the build order must work with Reactor switched off.** That is
  the always-works demo.
- **Record a backup screen capture** of a full round as soon as step 5 works.
  Live demos fail.
